# Plan: Meeting file upload and storage

**PRD:** docs/prd-meeting-file-upload-and-storage.md
**Дата:** 2026-08-19

Каждая фаза следует test-first подходу: сначала пишутся/расширяются e2e-тесты, покрывающие поведение фазы (тесты красные — фичи ещё нет), затем реализуется функциональность, затем тесты прогоняются и должны стать зелёными. Backend использует существующий Jest+Supertest e2e (`apps/api/test`). Для frontend в Фазе 3 добавляется Playwright test runner (в проекте пока есть только ручная визуальная проверка через Playwright MCP — для e2e-тестов нужен отдельный автоматический раннер).

## Фазы реализации

### Фаза 1: Backend — схема данных и базовый путь загрузка/скачивание (tracer bullet)

**Цель:** Минимальный рабочий путь — файл можно загрузить на встречу и скачать обратно через API.
**Затрагивает:** backend, database
**Задачи:**
- [ ] Написать `test/meeting-file.e2e-spec.ts` с тестами на загрузку и скачивание файла встречи (красные — эндпоинтов ещё нет)
- [ ] Добавить модель `MeetingFile` в `prisma/schema.prisma` (meetingId — уникальная связь 1:1 с `Meeting`, filename, size, mimeType, storagePath, uploadedAt), создать миграцию (`prisma:migrate:dev` + `prisma:generate`); настроить каталог хранения файлов на диске (в `.gitignore`), константы лимита размера (100Мб) и списка допустимых MIME-типов
- [ ] `UploadMeetingFileCommand`/`UploadMeetingFileHandler`: приём файла (multer/`FileInterceptor`), валидация размера и MIME-типа, сохранение файла и записи в БД
- [ ] `POST /meetings/:id/file` (загрузка) и `GET /meetings/:id/file/download` (скачивание) под `JwtAuthGuard`
- [ ] Прогнать `npm run test:e2e --workspace=api` — тесты из первого пункта должны стать зелёными

**Когда готова:** Тесты на загрузку/скачивание зелёные; авторизованный пользователь может загрузить файл на встречу через API и скачать его обратно.

### Фаза 2: Backend — метаданные, удаление, авторизация

**Цель:** Полный набор бэкенд-эндпоинтов для работы с файлом встречи.
**Затрагивает:** backend
**Задачи:**
- [ ] Расширить `test/meeting-file.e2e-spec.ts`: метаданные файла, замена файла при повторной загрузке, удаление (владельцем и попытка не-владельцем — 403), отказ при превышении лимита размера, 401 без авторизации на всех трёх эндпоинтах (красные)
- [ ] `GetMeetingFileQuery`/`GetMeetingFileHandler` + `GET /meetings/:id/file` — метаданные файла (имя, размер, MIME, дата загрузки)
- [ ] `DeleteMeetingFileCommand`/`DeleteMeetingFileHandler` + `DELETE /meetings/:id/file` — только организатор встречи (403 для остальных), удаляет запись в БД и файл с диска
- [ ] Логика замены файла при повторной загрузке (удаление старого файла с диска) в `UploadMeetingFileHandler`, если не сделано в Фазе 1
- [ ] Прогнать `npm run test:e2e --workspace=api` — весь `meeting-file.e2e-spec.ts` зелёный

**Когда готова:** `npm run test:e2e --workspace=api` зелёный, покрывает все критерии готовности, относящиеся к backend.

### Фаза 3: Frontend — инфраструктура e2e и отображение прикреплённого файла

**Цель:** Пользователь видит карточку файла (имя, размер, дата, ссылка на скачивание) на странице встречи; появляется автоматический e2e-раннер для frontend.
**Затрагивает:** frontend
**Задачи:**
- [ ] Установить и настроить Playwright test runner для `apps/web` (пакет `@playwright/test`, конфиг, npm-скрипт `test:e2e`)
- [ ] Написать Playwright e2e-тест: логин → открытие страницы встречи с прикреплённым файлом (файл создать через API-хелпер в тесте) → карточка показывает имя/размер/дату и рабочую ссылку скачивания (красный — страницы `/meetings/[id]` ещё нет)
- [ ] Реализовать `src/lib/meeting-file-api.ts`, страницу `src/app/meetings/[id]/page.tsx` (защищена так же, как `/`), компонент `FileCard` (+ пустое состояние без файла)
- [ ] Прогнать Playwright e2e — тест из второго пункта зелёный
- [ ] Визуальная проверка в браузере (Playwright MCP) + проверка по скиллу `ui-ux-pro-max`

**Когда готова:** Playwright e2e-тест на отображение файла зелёный; открытие встречи с прикреплённым файлом показывает карточку с рабочей ссылкой скачивания; проверено визуально.

### Фаза 4: Frontend — форма загрузки файла

**Цель:** Пользователь может загрузить (или заменить) файл встречи через UI с drag-and-drop и прогресс-баром.
**Затрагивает:** frontend
**Задачи:**
- [x] Написать Playwright e2e-тесты: загрузка файла через drag-and-drop/выбор кликом с отображением прогресса и обновлением карточки; отдельный тест на отклонение файла с недопустимым размером/типом с понятной ошибкой (красные)
- [x] Компонент загрузки: drag-and-drop зона + выбор файла кликом, подсказка по допустимым типам и лимиту 100Мб, иконка типа файла по MIME, прогресс-бар
- [x] Отправка на `POST /meetings/:id/file`; при успехе — обновление `FileCard`; при ошибке — сообщение без потери страницы; повторная загрузка заменяет карточку данными нового файла
- [x] Прогнать Playwright e2e — тесты из первого пункта зелёные
- [x] Визуальная проверка в браузере (Playwright MCP, включая крайние случаи) + проверка по скиллу `ui-ux-pro-max`

**Когда готова:** Playwright e2e-тесты на загрузку зелёные; пользователь загружает файл через форму, видит прогресс и итоговую карточку; ошибки валидации отображаются понятно.

### Фаза 5: Frontend — удаление файла и сквозной e2e-сценарий

**Цель:** Организатор может удалить файл; весь пользовательский сценарий покрыт e2e-тестом.
**Затрагивает:** frontend
**Задачи:**
- [x] Написать Playwright e2e-тесты: удаление файла организатором (карточка сменяется пустым состоянием), кнопка удаления не видна не-организатору; сквозной тест полного сценария — загрузка → отображение → скачивание → удаление (красные)
- [x] Кнопка удаления на `FileCard`, видима только организатору встречи; вызов `DELETE /meetings/:id/file`, возврат к пустому состоянию при успехе
- [x] Прогнать Playwright e2e — все тесты зелёные, включая сквозной сценарий
- [x] Визуальная проверка в браузере (Playwright MCP) + проверка по скиллу `ui-ux-pro-max`

**Когда готова:** Полный пользовательский путь (загрузка → отображение → скачивание → удаление) работает в UI и покрыт автоматическим e2e-тестом — все критерии готовности из PRD выполнены.
