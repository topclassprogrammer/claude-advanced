# Plan: Страница профиля пользователя и её редактирование

**PRD:** docs/prd-user-profile-page-and-editing.md
**Дата:** 2026-08-20

Каждая фаза следует test-first подходу: сначала пишутся/расширяются e2e-тесты, покрывающие поведение фазы (тесты красные — функциональности ещё нет), затем реализуется функциональность, затем тесты прогоняются и должны стать зелёными. Backend использует существующий Jest+Supertest e2e (`apps/api/test`), frontend — Playwright (`apps/web/e2e`).

## Фазы реализации

### Фаза 1: Backend — схема данных и профиль (просмотр + имя, tracer bullet)

**Цель:** Минимальный рабочий путь — авторизованный пользователь может получить свой профиль и изменить имя через API.
**Затрагивает:** backend, database
**Задачи:**
- [ ] Написать `test/profile.e2e-spec.ts` с тестами на `GET /users/me` (email, name — включая дефолт «часть email до `@`», если имя не задано) и `PATCH /users/me/name`, плюс 401 без токена (красные — эндпоинтов ещё нет)
- [ ] Добавить в `prisma/schema.prisma` поля `User.name` (nullable String), `User.avatarPath`, `User.avatarMimeType`, `User.avatarUploadedAt` (nullable) — задел под Фазу 2, создать миграцию (`prisma:migrate:dev` + `prisma:generate`)
- [ ] `ProfileModule` (CQRS, по образцу `MeetingModule`): `GetProfileQuery`/`GetProfileHandler` (email, вычисляемое `name` — часть email до `@`, если поле пустое) и `UpdateProfileNameCommand`/`UpdateProfileNameHandler`
- [ ] `GET /users/me` и `PATCH /users/me/name` под `JwtAuthGuard`
- [ ] Прогнать `npm run test:e2e --workspace=api` — тесты из первого пункта зелёные

**Когда готова:** Авторизованный пользователь может получить профиль (с дефолтным именем при отсутствии `name`) и изменить имя через API; тесты зелёные.

### Фаза 2: Backend — аватар (загрузка, удаление)

**Цель:** Полный бэкенд для загрузки, замены и удаления аватара.
**Затрагивает:** backend
**Задачи:**
- [ ] Расширить `test/profile.e2e-spec.ts`: загрузка аватара (успех, отклонение недопустимого MIME-типа, отклонение файла > 5 МБ), замена аватара при повторной загрузке (старый файл удаляется с диска), удаление аватара (возврат к заглушке), `avatarUrl`/метаданные в ответе `GET /users/me`, 401 на всех новых эндпоинтах (красные)
- [ ] `profile.constants.ts` — `MAX_AVATAR_SIZE_BYTES` (5 МБ), `ALLOWED_AVATAR_MIME_TYPES` (JPEG/PNG/WebP), каталог хранения (`apps/api/storage/avatars`, в `.gitignore`), по аналогии с `meeting-file.constants.ts`
- [ ] `UploadAvatarCommand`/`UploadAvatarHandler` (`FileInterceptor`, `diskStorage`, валидация типа/размера, удаление предыдущего файла при замене) и `DeleteAvatarCommand`/`DeleteAvatarHandler` (удаление файла с диска и очистка полей в БД)
- [ ] `POST /users/me/avatar` (загрузка/замена) и `DELETE /users/me/avatar` под `JwtAuthGuard`; эндпоинт отдачи файла аватара (`GET /users/me/avatar` или статическая раздача) для использования в `<img>` на фронтенде
- [ ] Прогнать `npm run test:e2e --workspace=api` — весь `profile.e2e-spec.ts`, покрывающий аватар, зелёный

**Когда готова:** Пользователь может загрузить, заменить и удалить аватар через API; недопустимые файлы отклоняются с понятной ошибкой; тесты зелёные.

### Фаза 3: Backend — смена пароля

**Цель:** Пользователь может сменить пароль через API, указав старый пароль.
**Затрагивает:** backend
**Задачи:**
- [ ] Расширить `test/profile.e2e-spec.ts`: успешная смена пароля (и последующий логин новым паролем), отказ при неверном старом пароле, отказ при пустом/слишком коротком новом пароле, 401 без токена (красные)
- [ ] DTO смены пароля (`oldPassword`, `newPassword`, class-validator) в `ProfileModule`
- [ ] `ChangePasswordCommand`/`ChangePasswordHandler` — сверяет `oldPassword` через `bcrypt.compare`, при несовпадении `UnauthorizedException`, иначе хеширует и сохраняет новый пароль
- [ ] `PATCH /users/me/password` под `JwtAuthGuard`
- [ ] Прогнать `npm run test:e2e --workspace=api` — тесты смены пароля зелёные

**Когда готова:** Пользователь может сменить пароль и залогиниться новым; неверный старый пароль и слишком короткий новый — отклоняются; тесты зелёные, backend-часть PRD полностью покрыта.

### Фаза 4: Frontend — страница профиля и отображение на главной

**Цель:** Пользователь видит свой профиль (имя, аватар или заглушка, email); аватар и имя видны рядом с email на главной странице.
**Затрагивает:** frontend
**Задачи:**
- [ ] Написать Playwright e2e: логин → открытие `/profile` показывает имя (в т.ч. дефолт — часть email до `@`), заглушку аватара при его отсутствии и email; аватар/имя, заданные через API-хелпер, отображаются на `/profile` и на главной странице в шапке (красные — страницы и клиента ещё нет)
- [ ] `src/lib/profile-api.ts` (`getProfile`, обёртка над `GET /users/me`)
- [ ] `src/app/profile/page.tsx` (маршрут `/profile`, защищена как `/`), компонент отображения аватара с заглушкой по умолчанию
- [ ] Обновить шапку `src/app/page.tsx`: рядом с email показать аватар (или заглушку) и имя пользователя вместо только email
- [ ] Прогнать Playwright e2e — тесты из первого пункта зелёные; визуальная проверка (Playwright MCP) + скилл `ui-ux-pro-max`

**Когда готова:** Открытие `/profile` показывает имя/аватар/email; аватар и имя видны на главной странице; проверено визуально.

### Фаза 5: Frontend — редактирование имени и аватара

**Цель:** Пользователь может изменить имя, загрузить/заменить и удалить аватар через UI.
**Затрагивает:** frontend
**Задачи:**
- [x] Написать Playwright e2e: изменение имени через форму обновляет `/profile` и главную страницу; загрузка аватара (drag-and-drop/клик) с валидным файлом обновляет аватар в обоих местах; загрузка недопустимого типа/размера — понятная ошибка без потери страницы; удаление аватара возвращает заглушку (красные)
- [x] Форма редактирования имени на `/profile` (или `/profile/edit`) — вызывает `PATCH /users/me/name`, обновляет отображение при успехе
- [x] Компонент загрузки аватара (drag-and-drop зона + выбор кликом, клиентская валидация типа/размера по константам, зеркалящим `apps/api`) — вызывает `POST /users/me/avatar`; кнопка удаления аватара — вызывает `DELETE /users/me/avatar`
- [x] `src/lib/profile-api.ts`: добавить `updateProfileName`, `uploadAvatar`, `deleteAvatar`
- [x] Прогнать Playwright e2e — тесты из первого пункта зелёные; визуальная проверка (Playwright MCP, включая ошибки валидации) + скилл `ui-ux-pro-max`

**Когда готова:** Пользователь редактирует имя и аватар (загрузка/замена/удаление) через UI, изменения видны на `/profile` и главной странице; ошибки валидации отображаются понятно.
