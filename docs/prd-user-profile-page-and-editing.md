# PRD: Страница профиля пользователя и её редактирование

**Дата**: 2026-08-20
**Статус**: Draft

# Цель
Авторизованный пользователь может посмотреть свой профиль и отредактировать имя, аватар и пароль, чтобы персонализировать аккаунт; аватар и имя видны и на главной странице рядом с email залогиненного пользователя.

## Пользовательские сценарии
- Пользователь открывает страницу профиля -> видит текущее имя, аватар (или заглушку по умолчанию) и email (не редактируется).
- Пользователь открывает страницу редактирования профиля, меняет имя -> сохраняет -> новое имя отображается в профиле и на главной странице.
- Пользователь загружает новый аватар (drag-and-drop или выбор файла) -> аватар сохраняется, заменяет предыдущий, отображается в профиле и на главной странице.
- Пользователь удаляет аватар -> профиль и главная страница возвращаются к отображению заглушки по умолчанию.
- Пользователь вводит старый пароль и новый пароль -> при совпадении старого пароля пароль меняется, пользователь может залогиниться новым паролем.
- Пользователь вводит неверный старый пароль при смене пароля -> получает понятную ошибку, пароль не меняется.
- Пользователь загружает аватар недопустимого типа или превышающий лимит размера -> получает понятную ошибку, аватар не сохраняется.
- Неавторизованный пользователь пытается открыть страницу профиля/редактирования или дёрнуть соответствующие эндпоинты -> получает отказ в доступе (401).
- У пользователя, ещё не задававшего имя, на главной странице и в профиле отображается имя по умолчанию — часть email до `@`.

## В скоупе
- Страница профиля (`/profile`): отображение имени, аватара, email (только чтение).
- Страница/форма редактирования профиля: изменение имени, загрузка/замена аватара, удаление аватара, смена пароля.
- Поле `name` в Prisma-модели пользователя (текстовое имя, редактируемое) и `avatarUrl`; для пользователей без явно заданного имени — вычисляемое отображаемое имя (часть email до `@`), без миграции существующих данных.
- Хранение аватара на локальной файловой системе сервера `apps/api`, аналогично файлам встречи; метаданные аватара (путь, MIME-тип, дата загрузки) — в БД, привязаны к пользователю.
- Эндпоинт получения профиля текущего пользователя (имя, email, ссылка на аватар).
- Эндпоинт обновления имени.
- Эндпоинт загрузки/замены аватара.
- Эндпоинт удаления аватара (возврат к заглушке по умолчанию).
- Эндпоинт смены пароля (принимает старый и новый пароль, проверяет старый перед сохранением нового).
- Отображение аватара и имени пользователя рядом с email на главной странице (`/`), в шапке, где сейчас показан только email.
- Отображение аватара и имени в самом профиле.
- Заглушка аватара по умолчанию, если пользователь его не загружал или удалил.
- Валидация загрузки аватара: допустимые типы JPEG/PNG/WebP, лимит размера 5 МБ; отказ с понятной ошибкой при нарушении.
- Валидация смены пароля: отказ при неверном старом пароле, отказ при пустом/слишком коротком новом пароле.

## Не в скоупе
- Смена email.
- Удаление аккаунта.
- Обрезка/редактирование изображения аватара на клиенте (кроп, поворот) — загружается файл как есть.
- Модерация/проверка содержимого аватара.
- История изменений профиля (аудит-лог).
- Двухфакторная аутентификация или иные меры безопасности при смене пароля (например, подтверждение по email, разлогин других сессий).
- Публичные профили других пользователей — виден и редактируется только собственный профиль.

## Технические ограничения
- Monorepo: NestJS backend, Next.js frontend, CQRS через CommandBus/QueryBus — новый функционал реализуется по тому же паттерну (`ProfileModule` или расширение `UsersModule`), что и существующие модули.
- Prisma + PostgreSQL: модель `User` расширяется полями `name` (nullable) и `avatarUrl` (nullable) — миграция обязательна.
- Максимальный размер аватара: 5 МБ.
- Допустимые типы аватара: JPEG, PNG, WebP.
- Аватар хранится на локальном диске сервера `apps/api`, по аналогии с файлами встречи (`apps/api/CLAUDE.md`, `docs/research-meeting-file-upload.md`).
- Смена пароля хешируется тем же механизмом (bcrypt), что и при регистрации.
- Отображаемое имя по умолчанию (часть email до `@`) вычисляется на лету там, где `name` не задано — не требует backfill существующих строк в БД.

## Критерии готовности
- [ ] Авторизованный пользователь видит страницу профиля со своим именем, аватаром (или заглушкой) и email.
- [ ] Авторизованный пользователь может изменить имя через форму редактирования, изменение отображается в профиле и на главной странице.
- [ ] Авторизованный пользователь может загрузить/заменить аватар через форму редактирования, новый аватар отображается в профиле и на главной странице.
- [ ] Авторизованный пользователь может удалить аватар — профиль и главная страница возвращаются к заглушке по умолчанию.
- [ ] Пользователь без заданного имени видит на главной странице и в профиле имя по умолчанию (часть email до `@`).
- [ ] Авторизованный пользователь может сменить пароль, указав верный старый пароль и новый пароль, и залогиниться новым паролем.
- [ ] Смена пароля с неверным старым паролем отклоняется с понятной ошибкой, пароль не меняется.
- [ ] Загрузка аватара недопустимого типа или превышающего 5 МБ отклоняется с понятной ошибкой, аватар не сохраняется.
- [ ] Неавторизованный запрос к эндпоинтам профиля (просмотр, изменение имени, загрузка/удаление аватара, смена пароля) отклоняется (401).
- [ ] E2E-тесты покрывают все новые API-эндпоинты
- [ ] Typescript strict-mode проходит без ошибок (`npm run typecheck`)
- [ ] Typescript strict-mode проходит без ошибок (`npm run typecheck`)
