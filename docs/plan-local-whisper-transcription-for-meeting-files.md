# Plan: Транскрибация аудио/видео файлов встречи через локальный Whisper

**PRD:** @docs/prd-local-whisper-transcription-for-meeting-files.md
**Дата:** 2026-08-23

## Фазы реализации

### Фаза 1: Backend — модель данных и локальный пайплайн транскрибации

**Цель:** После загрузки mp4/mp3 файла встречи транскрибация автоматически запускается через локальный Whisper (модель "low"), статус и текст сохраняются и доступны через API только организатору встречи; транскрипт удаляется вместе с файлом.
**Затрагивает:** backend, database
**Задачи:**
- [ ] Prisma-модель транскрипта файла встречи (статус PENDING/PROCESSING/COMPLETED/FAILED, текст — nullable, связь один-к-одному с `MeetingFile`, `onDelete: Cascade`), миграция.
- [ ] Сервис локального запуска Whisper (модель "low") над файлом с диска, возвращающий распознанный текст или ошибку.
- [ ] Автозапуск транскрибации: после успешной загрузки файла встречи с MIME-типом mp4/mp3 создаётся запись со статусом PENDING, запускается обработка, статус переводится в PROCESSING, затем в COMPLETED (с текстом) или FAILED (при ошибке); для остальных MIME-типов запись не создаётся.
- [ ] Отдача статуса и текста транскрипта через API (расширение существующего списка файлов встречи или отдельный эндпоинт), доступ — только организатору встречи, по аналогии с остальными операциями над файлами встречи.
- [ ] Unit/e2e-тесты: автозапуск на mp4/mp3, отсутствие запуска на других MIME-типах, переходы статусов, каскадное удаление транскрипта при удалении файла, 403/404 для не-организатора.

**Когда готова** Загрузка mp4/mp3 файла встречи создаёт и доводит до конца (COMPLETED/FAILED) запись транскрипта, доступную через API только организатору; удаление файла удаляет транскрипт; всё покрыто e2e-тестами.

### Фаза 2: Frontend — отображение статуса и текста транскрипта

**Цель:** На странице встречи пользователь видит статус транскрибации рядом с файлом и текст транскрипта после завершения, без ручной перезагрузки страницы.
**Затрагивает:** frontend
**Задачи:**
- [ ] Отображение статуса транскрибации ("в процессе" / "готово" / "ошибка") рядом с соответствующим файлом на странице встречи.
- [ ] Периодическое обновление статуса (поллинг) для файлов со статусом "в процессе", остановка поллинга после перехода в "готово"/"ошибка".
- [ ] Отображение текста транскрипта на странице встречи после перехода статуса в "готово".
- [ ] Отображение состояния "ошибка" без блокировки остального функционала страницы встречи.
- [ ] Playwright e2e-тест: статус появляется после загрузки mp4/mp3, обновляется без перезагрузки страницы, текст транскрипта отображается после завершения.

**Когда готова** Пользователь на странице встречи видит актуальный статус транскрибации и итоговый текст без перезагрузки страницы; проверено e2e-тестом.
